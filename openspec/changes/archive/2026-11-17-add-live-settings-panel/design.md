# Design

## Context

动机见 proposal.md。现有实现决定本次需要跨模块调整：

- `src/index.ts` 的 `registerSettingsMenu` 注册逐项菜单，启动时保存 `g_settings` 快照；本地标签开关和全部重置直接刷新页面。
- `src/utils/setting.ts` 使用同一 GM 存储键保存扁平配置；`GlobalSettings` 有 13 个用户字段和内部 `version` 字段。数值 prompt 使用 `Number(value) || default`，无法正确保存部分有效的零值。
- `preview.ts`、`sort.ts` 在初始化时解构配置，并以一次性初始化标记阻止重建。预览 LRU 在模块或功能初始化时固定容量。
- 本地标签在 document-start 拦截页面请求，随后挂载入口、事件和观察器；只移除界面不能完整停用统计。下载记录和标签数据已有 GM 跨标签页同步机制。
- 底层参数分布于 `constants/index.ts`、下载/请求/缓存服务、数据库连接、标签工具和动图播放器。没有已有 OpenSpec 能力规格，也没有现成自动化测试套件。

## Goals / Non-Goals

**Goals:**

- 一份字段清单驱动面板、输入解释与校验；一份有效配置快照供功能读取，消除各模块独立保存的过期设置。
- 先完成“面板编辑—保存—当前页面采用新值”的最小闭环，再逐层接入高级配置。
- 将功能启停、当前任务快照和后续操作配置明确区分，保持已有操作可完成、状态可共享。

**Non-Goals:**

- 不新增自动播放控制、下载目录策略、导入导出、配置预设、语言切换或独立设置路由。
- 不开放外观，不重写现有 UI 主题或播放器，不配置协议/格式/站点分页规格；不增加兼容层、配置迁移器或新的运行依赖。
- 不因保存自动执行排序、重新抓取数据、重启原图下载或重建正在播放的动图。

## Decisions

### 1. 功能分组与默认隐藏的高级设置

用户已选择“功能分组 + 点击展开高级设置”。常用区按作品预览（含作品下载）、作品排序、本地标签排列；高级设置分为缓存、下载管理、网络、内部调度，初始折叠，重新打开面板仍折叠。

考虑过将全部字段直接按源码模块平铺；这会把用户日常操作与底层数值放在同一层级。采用用户选定的分组。面板使用右下角的单实例非模态窗口，限制在视口内滚动，操作区持续可访问；不增加外观配置入口。

```text
设置                                  关闭
作品预览（含作品下载）      字段 / 恢复默认
作品排序                    字段 / 恢复默认
本地标签                    字段 / 恢复默认
▸ 高级设置
全部恢复默认                         保存
```

沿用 jQuery 与原生表单控件，所有文案放入 `Texts`。具体宽高、DOM 类名、内部布局和样式由实现者按既有面板约定决定。Tampermonkey 只保留一个配置入口；现有“清除缓存”“查看缓存占用”维护命令保留原行为，不与恢复默认合并。

### 2. 单一配置定义与完整字段清单

保留扁平的 `GlobalSettings` 和现有有效字段键。默认值仍以 `g_defaultSettings` 为唯一来源；增加简单的字段描述清单（建议 `src/constants/settings.ts`），包含键、分组、控件种类、单位、文案引用及基本范围。跨字段校验集中在设置工具中，不构建通用表单框架。

`version` 继续作为内部元数据，不进入描述清单。单项重置引用同一默认值；全部重置遍历用户字段，不覆盖 `version`。不保留已替换的逐项菜单助手和有效可调数值的重复常量来源。

下表中的新键名是设计选择，实现时可在保持语义和统一来源的前提下调整。时长持久化为毫秒，空间为字节；面板显示表中的易读单位并转换输入。

#### 派生值和明确排除项

- 图片解码 LRU 容量 = 预加载数量 × 2；翻译缓存淘汰目标 = 容量 ÷ 2 后向下取整。两者无独立字段。
- 悬停检测内部计时继续由 `previewDelay` 按现有比例计算；单位换算、百分比、几何坐标等继续计算。
- 排除 CSS 数值、颜色、收藏数着色阈值、标签数量达到 10 后切换图标的纯显示阈值。
- 排除 HTTP 状态码、ZIP 魔数/记录长度/字段偏移、枚举数值、数组下标、站点每页 48 件作品的分页语义。
- 排除旧浏览器 data-URL 分支的 10 帧/200 ms 节流及空闲回调缺失时的兼容等待；未被实际调用的工具函数默认延迟不新增字段。触及这些实现时按 Chrome >= 107 删除已过时路径，不将其包装成可配置能力。

### 3. 草稿、校验与保存使用同一条路径

面板保存 `baseline`、`draft` 和明确编辑的字段集合。单项恢复默认将该键标记为明确编辑；全部恢复默认将全部用户键标记为明确编辑，即使某字段当时恰好已等于默认值。

保存时从最新有效快照取内部元数据及未编辑字段，覆盖明确编辑的草稿字段，再完整校验、单次 `GM_setValue` 写入，最后更新内存快照并通知订阅者。成功后面板仍打开，草稿与有效配置对齐；写入抛错则保留旧有效配置及草稿。关闭直接放弃草稿，不增加额外确认流程。

面板描述清单提供基本类型和范围；跨字段关系单独验证。拒绝无效输入并定位字段，不使用 `Number(value) || default`。高级字段出错时自动展开。主要约束：

- 页数、数量、字节容量为正整数；最低收藏数为非负整数；翻译缓存容量至少 2。
- TTL、超时、探测间隔和长按时间为正有限值；交互延迟、防抖、延迟落盘允许 0；单位转换后仍需有限且有效。
- `0 < downloadProgressPersistMs <= downloadHeartbeatMs < downloadOwnerTimeoutMs`。
- 请求重试最短 1 秒；动图下载分块至少 64 KiB；尾部探测至少容纳 ZIP 固定尾记录。以上下限是本次设计选择，不是对 Pixiv 速率安全性的承诺。
- 排序依据必须是现有两个枚举值；最大尝试次数为正整数或 null。其余界面数值输入为空时拒绝保存。

不构建事务回滚框架：保存的持久化边界是一次配置对象写入；内存通知同步完成后提示成功。持久化缓存清理是已安排的异步工作，失败通过现有日志记录，不谎报已清理，也不回滚已保存配置。

### 4. 共享有效快照与跨标签页同步

`utils/setting.ts` 维护当前有效配置，首次读取通过既有 GM 存储加载，其后从内存取值，避免每次鼠标事件反序列化。提供最小的读取、完整保存和订阅接口，启动时只安装一个 GM 配置变更监听。复用现有存储键与授权；缺少当前字段使用默认值，不添加旧键映射、迁移或双读。

其他标签页变更也走同一内存更新和功能通知路径。面板未编辑字段随远程变更更新，明确编辑字段保留；保存时合并最新快照，不覆盖其他标签页对不同字段的修改。同一字段最后一次保存覆盖先前值，不增加冲突弹窗或修订历史。

面板关闭移除其订阅，功能订阅由功能模块管理。继承的 `version` 始终来自最新有效快照，不参与用户字段恢复。

### 5. 按功能接入实时配置，不重载脚本

| 模块 | 接入方式及保存后的边界 |
|---|---|
| 预览 | 委托只安装一次，处理事件时读取当前快照；初始关闭也能随后开启。关闭总开关时重置当前预览、停止预览播放器并取消预览计时，不取消原图下载。悬停参数改变时取消旧的待触发计时；其余预览计时在下次对应交互读取新值。 |
| 作品链接 | 保存关闭强制新标签页时，仅撤销脚本改写的属性和事件，恢复页面原本行为；脚本生成的排序作品链接采用相同设置。作者/标签链接保持原有语义。 |
| 排序 | 每次用户发起排序时读取一次完整排序配置，当前任务保留自己的快照；已渲染结果不因保存而重新请求、重排或过滤。 |
| 本地标签 | 请求拦截在 document-start 只安装一次，是否克隆响应或记录统计按当前开关判断，异步响应落盘前再次判断。UI 启用时挂载，停用时断开观察器、移除 UI 与相关事件、取消浮层计时并冲刷未落盘状态；再次启用不会叠加处理。 |
| 下载记录 | 数量上限在后续记录写入/更新时应用，保留活动项；进度持久化间隔在后续进度事件读取。心跳调整只重设一个现有循环，先更新本标签页拥有的活动记录，不重启文件请求。 |
| 网络 | 新请求/播放器读取超时、最大尝试次数及分块设置；已经发出的请求和创建的播放器保持参数。后续新开始的一次重试等待读取当前间隔，不重启已开始的等待。 |
| 调度 | 下一次对应的探测、清理或数据库打开采用新配置，不重新初始化已完成的探测。活跃标签观察器的防抖、浮层计时和延迟落盘在参数变化时取消旧计时并按需重新安排；待保存标签必须保留并落盘。 |

收紧下载失联阈值不追溯套用到变更前的一次心跳：配置变更时已知的活动记录，在观察到后续心跳前沿用原有效失联时间；新心跳后使用新值。没有后续心跳仍按原超时失联，避免无限保活。该边界使用配置变更时的记录快照处理，不引入持久化记录格式迁移。

`initializeEarly` 不再用启动快照永久决定预览能否启用；`initializeDom` 及标签拦截同样不再成为一次性的开关门。去掉已经替换的 toggle/prompt 菜单助手及刷新逻辑，升级提示和独立缓存维护保持原职责。

### 6. 缓存按当前策略访问并可收缩

将有效可调常量的消费者改为读取当前设置；在单次缓存访问或清理批次中使用一致快照。可变信息有效期和预览额外容忍仍按现有调用语义叠加，不混同静态信息有效期。

沿用 `createLRUCache`，只增加必要的容量调整/淘汰能力；预加载数量变更时同步调整派生的解码缓存容量。保存容量变小的配置后立即约束内存缓存，安排已有持久化清理逻辑按新上限执行；去除只允许启动时执行一次的限制对配置变更清理的阻挡。

TTL 读取按新值判断，不为应用设置清空所有缓存、不主动拉取数据、不升级 IndexedDB 结构。全部恢复默认是保存字段，不调用清空维护函数；下载记录在后续正常保留策略中处理，标签用户数据始终保留。

### 7. 验证保持针对性

现有项目没有测试套件。实现时只为有效零值、完整保存失败不改变有效配置、草稿与远程变更合并、一次性启停和派生容量调整补最小可运行回归证明；不引入通用测试框架或机械镜像测试。

执行类型检查和触及文件的 ESLint。构建如需验证使用临时输出目录，不改跟踪的 `dist/`；在 Pixiv/Tampermonkey 浏览器中覆盖两份规格的关键场景，尤其是初始关闭后开启、保存不刷新、运行中排序、活动下载、标签重复启停和双标签页。无法进行浏览器验证时明确报告。

## Risks / Trade-offs

- [设置范围较大，容易遗漏常量消费者] → 以本设计清单为覆盖基准，对每个被替换常量核对引用；明确排除项不生成配置。
- [直接重跑初始化会累积事件/观察器] → 预览委托一次注册，本地标签提供明确启停与清理；重复启停作为浏览器回归场景。
- [调整下载心跳导致活动任务被误判失联] → 先续期并重设单一循环，旧心跳按原有效超时处理到下一次心跳，不重新发起下载。
- [放宽缓存造成内存或磁盘占用增加] → 明确单位与容量含义，保留原默认值，保存后按新策略淘汰；不自动提高请求并行度。
- [缩短 TTL/重试间隔增加 Pixiv 请求] → 保持串行、缓存复用及重试等待，设置正值/最短重试间隔约束，不在保存时执行网络操作。
- [部分启动专用参数在本页不再有后续使用机会] → 标注“后续对应操作使用”，不为展示效果重新探测已挂载的 UI 或重开数据库；后续正常打开页面也会使用新值。
- [多标签页覆盖未保存草稿] → 明确编辑键与最新配置合并，全部恢复默认明确覆盖全部用户键，内部元数据独立保留。

本次仅提交规划。实施按 tasks.md 的顺序完成最小闭环，再逐层接入高级配置；不提供迁移脚本。正式发布另行按项目 release 流程提升版本并生成 dist，本提案和普通实现不包含发布操作。
